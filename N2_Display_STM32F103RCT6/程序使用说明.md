# 氮气浓度读取与三位数码管显示程序

工程入口：`MDK-ARM/N2_Display.uvprojx`。控制器为 STM32F103RCT6，内部 HSI 经 PLL 配置为 64 MHz。程序已加入当前 Keil 工程，无需手工添加源文件。本次没有调用编译器、链接器或下载工具。

## 接线与运行

传感器供电接 5 V，与 STM32 共地；传感器 R/RX 接 PA9/USART1_TX，T/TX 接 PA10/USART1_RX。USART1 使用 9600、8N1，默认从机地址 1。USART2 使用 PA2/TX、PA3/RX，115200、8N1，输出诊断文本；连接电脑时使用 3.3 V TTL USB 转串口，电脑 RX 接 PA2 并共地。

数码管为三位共阴，A～G、DP 接 PB8～PB15，段线高电平点亮。DIG1、DIG2、DIG3 分别接 PA0、PA1、PA4，对应左、中、右三位，经 NMOS 低侧驱动，位选高电平有效。PD2 为状态 LED，高电平点亮；LED 与每根段线都应有合适的限流电阻。完整封装脚号见《接线与配置说明.md》。

上电后自动启动 TIM3 的 1 ms 扫描中断和 USART1 字节接收中断；启动约 200 ms 后发出第一次读取，此后每秒查询一次。程序不强制等待 180 s，按传感器返回的状态字识别预热。

| 场景 | 三位数码管 | PD2 LED |
| --- | --- | --- |
| 有效值 0 | `0.0`，左位空白 | 正常慢闪 |
| 有效值 5.6 | `5.6`，左位空白 | 正常慢闪 |
| 有效值 78.1 | `78.1` | 正常慢闪 |
| 有效值 99.9 | `99.9` | 正常慢闪 |
| 有效值 100 | `100`，不点亮小数点 | 正常慢闪 |
| 有效值 99.95 | 四舍五入为 `100` | 正常慢闪 |
| 上电等待、传感器预热或通信中断 | `---` | 快闪 |
| 气体类型不符、单位不符、未知小数编码、传感器故障、超量程、Modbus 异常 | `Err` | 快闪 |
| 预警、低报、高报、STEL/TWA 报警，浓度数据有效 | 仍显示浓度 | 快闪 |

正常慢闪每 500 ms 翻转一次电平，即约 1 Hz 完整明灭；快闪每 125 ms 翻转一次，即约 4 Hz。三位扫描一帧 3 ms，每位刷新约 333 Hz；切换时先关闭全部位选，再改段码，最后选中一位。

有效范围为 0～100 %VOL。超过 100 的原始测量值显示 `Err`，不会强制限幅成 100。整数浓度也显示一位小数，例如传感器返回 78 %VOL 时显示 78.0。程序采用整数运算及四舍五入，不使用浮点格式化。

## 氮气协议依据

已重新核对根目录《4MZ气体传感器模组规格书v1.37新版.pdf》：

- 第 7 页：Modbus RTU，默认地址 0x01，9600、8N1，读取功能码 0x03，CRC 低字节在前。
- 第 8 页：寄存器 0x0000 包含单位、小数位；0x0001 是当前浓度；0x0004 是量程；0x0005 低字节是状态；0x0008 高字节是气体类型。
- 第 9 页：%VOL 单位编码为 0x4；小数位字段的 0/4/8/C 分别对应 0/1/2/3 位小数。
- 第 10 页：N2 气体类型为十进制 64，即 0x40；O2 为 67，N2O 为 65，程序会区分这些类型。

每次发送八字节二进制命令 `01 03 00 00 00 0A C5 CD`，读取十个寄存器。正常应答为 25 字节，包含 `01 03 14`、20 字节数据和 2 字节 CRC。异常应答为 5 字节 `01 83 异常码 CRC低 CRC高`。

先检查应答长度、从机地址、功能码及 CRC，再处理浓度。除预热状态外，仅允许气体类型 `(reg8 >> 8) == 0x40` 且单位为 %VOL 的应答进入测量显示。小数位从寄存器解析，不直接假定传感器总是返回一位小数。

例如 `reg0=0x4400`、`reg1=781`、`reg5=1`、`reg8=0x4000` 表示氮气浓度 78.1 %VOL。该组合是协议测试数据，不是实测数据。气体满量程可在 `g_n2_diagnostics.sample.registers[4]` 或原始帧中查看；本手册没有单列氮气型号量程表。

程序只发送 0x03 读取命令，不会发送地址更改、工作模式修改、报警阈值写入或标定命令。若实物被设置为主动上报而不能正常响应查询，应先按厂商资料设置为被动查询模式，或调整应用程序支持实物的上报模式。

## 通信容错

- 接收中断把字节和到达时间放入 128 项环形队列；协议解析、格式化及串口打印均在主循环执行。
- 按 ISR 记录的时间判定帧间隔，避免调试输出造成虚假的断帧。
- 丢弃错误地址、功能码和长度；CRC 失败时滑动寻找下一帧头，不显示坏帧内容。
- 单次请求 500 ms 内未获得完整有效应答时显示 `---`，下次轮询继续重试。
- 最后一次有效测量超过 3 s 未更新时清除旧数值，包括持续收到杂散数据而不能发起新查询的情况。
- 串口错误、接收重装失败或队列溢出后，中止接收、清除错误并重新挂接字节中断；失败时每 50 ms 再尝试。
- 不会把通信失败显示为正常浓度 0.0。

## 调试输出

USART2 正常行示例：

```text
N2 result=0 gas=0x40 meta=0x4400 raw=781 status=0x01 value=78.1 %VOL alarm=0 crc_bad=0 timeout=0
```

| result 值 | 含义 |
| --- | --- |
| 0 | 有效 N2 测量 |
| 1 | 预热 |
| 2 | 长度、地址、功能码或 CRC 错误；通常继续等到超时 |
| 3 | Modbus 异常应答 |
| 4 | 气体类型不是 N2 |
| 5 | 单位不是 %VOL |
| 6 | 小数位编码不在手册定义内 |
| 7 | 传感器状态为故障/无效测量 |
| 8 | 浓度超过 100 %VOL |

无效应答只打印原始字段，不打印一个伪造的有效浓度。通信中断打印 `N2 response timeout`。Keil Watch 可查看 `g_n2_diagnostics`：十个原始寄存器、解析结果、坏帧、超时、串口错误及队列溢出计数。`valid_frames` 是通过校验的应答数，包括预热、故障和异常应答，不等同于有效浓度次数。

若持续为 result=4/5/6，先记录气体码、reg0 和实际型号，核对厂商协议版本。不要直接关闭气体校验或猜固定小数位。
